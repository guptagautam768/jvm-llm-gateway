# jvm-llm-gateway v1.0.0 — draft

**Status: draft. No git tag and no GitHub release.** The owner decides go-live after review.

This note describes the tree that implements SDR-0001 v1.0. It is not a claim that the tag exists.

## What a caller can do

Point an OpenAI SDK or curl at the gateway.

- `POST /v1/chat/completions` (JSON and SSE)
- `POST /v1/embeddings`
- `GET /v1/models` (routing table, no caller key)

The gateway authenticates `lgw_` caller keys, rate-limits and budgets per tenant, redacts configured PII before egress, caches eligible chat responses, records a usage row, and routes aliases across OpenAI, Anthropic, and Ollama with Resilience4j retry, circuit breaking, and fallback.

A local run without paid keys is `docker compose -f docker-compose.yml -f docker-compose.ollama.yml up --build`, after pulling `llama3.2` and `nomic-embed-text`. `./scripts/demo.sh` runs the same flows against WireMock.

## Decisions

Accepted ADRs 0001–0014. [ADR-0015](../adr/0015-ollama-webclient-and-public-embeddings.md) is **Proposed**. It is why Ollama is a WebClient adapter and why embeddings skip providers that cannot embed instead of failing startup. Rejecting that ADR means replacing the Ollama client and the skip rule. OpenAI and Anthropic chat routing do not depend on it.

## What this is not

- Not a measured latency SLO. NFR-001 remains a proposal. No load test was run for this draft, so this note has no throughput or percentile numbers.
- Not invoice-grade cost. Prices are a configured table. Ollama defaults to zero.
- Not a compliance certification. PII detection is a regex baseline.
- Not an admin UI, a bill, or a Kubernetes operator.

## Verify

`./gradlew build` on Java 21 with Docker. CI runs that command and uploads the JaCoCo report. There is no coverage gate.

## Operator notes

- Management port 8081 is bound to localhost in Compose. The API port does not serve actuator.
- Shutdown is graceful (20s) and the usage-ledger buffer then drains for up to 5s. Inserts are async. A failed insert is a metric, not a client error.
- Changing `gateway.cache.semantic.dimensions` requires `FT.DROPINDEX gateway:cache:semantic` on an existing Redis.
